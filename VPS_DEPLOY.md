# Развёртывание MemeCast на VPS

Конфигурация рассчитана на Ubuntu 22.04/24.04, Docker Compose и один экземпляр приложения. База SQLite и загруженные медиа хранятся в постоянном Docker-томе. Caddy принимает обычные HTTP-запросы на публичный IP сервера; домен не требуется.

## 1. Подготовка IP

У VPS должен быть постоянный публичный IPv4. Найдите его в панели хостинга, например `203.0.113.10`. Если адрес динамический, ссылки из Twitch и OBS перестанут работать после его смены.

## 2. Подготовка VPS

Установите Docker Engine с Compose plugin и откройте входящий TCP-порт 80. Скопируйте проект на сервер и перейдите в его каталог.

Создайте production-конфигурацию:

```bash
cp .env.production.example .env.production
openssl rand -hex 24
```

В `APP_URL` укажите публичный IP вместе с протоколом, например `http://203.0.113.10`. Выберите `ADMIN_LOGIN`, а результат второй команды вставьте в `ADMIN_PASSWORD`. Пароль должен содержать не меньше 16 символов, отличаться от логина и не использоваться на других сайтах. Это единственные данные для входа в кабинет администратора. `GIPHY_API_KEY` необязателен, если внешний поиск GIPHY не используется.

Оставьте `ADMIN_LOCAL_ONLY=true`. Поскольку сайт работает по IP и обычному HTTP, этот режим не даёт передать административный пароль по незашифрованному интернет-соединению. Публичная страница зрителей и OBS при этом остаются доступны по IP.

## 3. Запуск

```bash
docker compose --env-file .env.production up -d --build
docker compose ps
docker compose logs -f app
```

После успешного запуска создайте на своём компьютере SSH-туннель. Команду нужно запускать в отдельном терминале и оставлять его открытым на время работы в кабинете:

```bash
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:8081 root@IP-СЕРВЕРА
```

Если для SSH используется другой пользователь или порт, подставьте их, например `ssh -p 2222 -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18080:127.0.0.1:8081 user@IP-СЕРВЕРА`. Затем откройте `http://127.0.0.1:18080/login` и войдите с помощью `ADMIN_LOGIN` и `ADMIN_PASSWORD`. Порт `8081` на VPS публикуется Docker только на `127.0.0.1`, поэтому открыть административный туннель напрямую из интернета нельзя. Демо-кабинет и административный параметр `demo=1` в production отключены. Скопированные из кабинета публичная и OBS-ссылки по-прежнему будут содержать адрес из `APP_URL`, а не локальный адрес туннеля.

В кабинете будут сформированы готовые ссылки:

- `http://IP-СЕРВЕРА/s/имя-канала` — для баннера или панели Twitch;
- `http://IP-СЕРВЕРА/overlay/секретный-токен` — для Browser Source в OBS.

Не устанавливайте `ADMIN_LOCAL_ONLY=false`, пока у приложения нет HTTPS: обычный HTTP не шифрует логин, пароль и cookie сессии. Если позже появится домен с HTTPS, локальное ограничение можно отключить.

## 4. Обновление

```bash
git pull
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production up -d --build
docker image prune -f
```

Постоянный том с базой и медиа при пересборке не удаляется. Не запускайте `docker compose down -v`: ключ `-v` удалит пользовательские данные.

## 5. Резервная копия

```bash
docker compose exec -T app tar -C /data -czf - . > memecast-backup-$(date +%F).tar.gz
```

Для восстановления остановите приложение, распакуйте архив обратно в `/data`, затем запустите Compose. Перед копированием особенно важной базы рекомендуется временно остановить контейнер `app`, чтобы SQLite WAL гарантированно был согласован.

## 6. Диагностика

```bash
docker compose ps
docker compose logs --tail=200 app
docker compose logs --tail=200 caddy
curl -fsS http://IP-СЕРВЕРА/api/health
```

После обновления проверьте, что в `.env.production` есть `ADMIN_LOCAL_ONLY=true`. Файл `.env.production` не хранится в Git и не изменяется командой `git pull`.

Если после изменения логина или пароля открытая сессия завершилась, это нормально: войдите заново с новыми данными из `.env.production`.
